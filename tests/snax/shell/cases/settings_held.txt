# A write to any read-write CSR while the unit is busy is held until E + 1
# (snax-forge D168), so a group's settings stay constant through its run: the
# RTL's control unit reads JOBS and JOB_BEATS live from the csr, with no copy.
# A fold group with a scalar (TreeAccumulate, L = 1): START 0, JOBS 1,
# JOB_BEATS 2, K1 3, STATUS 4, BUSY_COUNTER 5. A run of J jobs of T beats
# started in a fires J * T times from a + 1 and pushes its last result one
# cycle later: E = a + J * T + 1, busy a + 1 .. E.
#   - run 1 (c3, JOBS 1, T 2, K1 7): fires c4, c5, E = 6. A read of JOBS in
#     c4 is answered at once (reads are never held); c5's JOBS 2 is held
#     through E and taken in c7 = E + 1.
#   - run 2 (c9, JOBS 2, T 2): E = 9 + 4 + 1 = 14, so c5's write was taken
#     (with JOBS 1 it would end in 12); c10's JOB_BEATS 3 is held until c15.
#   - run 3 (c16, JOBS 2, T 3): E = 16 + 6 + 1 = 23; c17's K1 9 is held until
#     c24, so run 3 still gets K1 7 and run 4 gets 9.
#   - run 4 (c25, JOBS 2, T 3, K1 9): E = 32; c26's START with bit 0 clear is
#     held until c33 too, then taken and does nothing: no run, done stays
#     (STATUS 2), BUSY_COUNTER keeps run 4's busy cycles, c26 .. c32: 7.
csrs START JOBS JOB_BEATS K1:32
